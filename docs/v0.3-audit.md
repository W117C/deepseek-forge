## 0. 一句话结论

**真实 Registry / 签名 / 扫描 / 审核 / 安装全链路（服务端 + CLI）已经存在且被 203 项 e2e 验证；但 Marketplace 前端（forge/）的数据层 100% 来自 mock.ts + localStorage，与真实 Registry 零连接——v0.3 的全部工作就是把这两半接上，并按规范补齐数据层（SQLite / Package-Version-Artifact 分离 / 状态机 / Publisher 模型 / API 客户端层）。**


## 3. Existing APIs（lib/registry-server.mjs 全量路由，源码行号核实）

## 4. Existing Data Flow（核实后的现状）

```
发布：CLI 打包(tar) → sha256 → ed25519 签名 → POST /v1/publish（Bearer token）
      → 服务端验签 → 验哈希 → 解包静态扫描 → 定级 trust →
      白名单发布者：写入 db.agents[id].versions[version]（内存 + registry.json 全量落盘）
      非白名单：写入 db.pending → POST /v1/review 审批后入库
下载：CLI GET /v1/agents/:id → artifactUrl（HMAC 签名 URL）→ GET 制品 →
      先验哈希（header x-agenthub-sha256）→ 再验签名 → 解包 → 本地安装（快照→pnpm→健康检查）
前端（现状，断裂）：forge 页面 → import mock.ts → 假列表/详情/搜索/安装(仅 localStorage)/发布(仅 localStorage)
```

## 5. Existing Security Model

- 服务端零执行第三方代码（只静态扫描，不解包执行）✅
- 发布验签 ed25519 + 验哈希 sha256 + trust-on-first-use 公钥 ✅
- 服务端扫描定级（不信任自报 trust）+ 审核队列 + blocked 客户端拒绝 ✅
- 发布/审核端点鉴权（Bearer + operatorToken，配置开启；e2e-auth 覆盖 401/冒用）✅
- 客户端安装前验哈希→验签→才解包 ✅（防篡改双测 e2e）
- 评分限流 / 安装幂等 / 制品下载限速 / 签名 URL 防盗链 ✅
- 快照回滚 / 备份恢复 ✅
- **缺口**：前端无任何鉴权面（浏览器调 API 的 api_tokens 体系缺失）；Registry 尚无公网实例（HTTPS 部署未执行）；CORS 未配置。

## 8. Technical Debt

1. Registry 存储 = 单 JSON 文件全量重写（registry.json）：无 schema version、无事务、无并发保护、无迁移；数据量增长后写入放大。
2. 数据模型扁平：db.agents[id].versions[ver] 内联 manifest/scan/signature——Package / Version / Artifact 未分离；无统一包状态机（只有 pending + trust）。
3. Publisher 模型缺失：只有 publishers{id:publicKey} + publisherTokens；无 slug/name/avatar/website/github/verified 等字段。
4. 前端类型（forge/src/types.ts）与服务端模型不一致：TrustLevel 用 verified/scanned/community/unverified（与后端 trust 语义不同）；PackageMeta 是扁平展示模型（version 单值），无 versions/status 概念。
5. CLI bin 仍叫 agenthub，而产品名是 forge（规范要求 forge publish / forge install）。
6. 文档过时：docs/deployment.md 的「Registry CLI flag 透传待补」等项实际已实现。
7. lib/registry-server.mjs 21KB 单文件（路由+存储+扫描+webui 混合）。
8. CORS / 前端 API 客户端层缺失（前端一旦接 API 就会撞同源策略）。

## 9. Risks（生产部署）

1. **Marketplace 展示假数据**：用户看到 975 行 mock 里的包，安装按钮是假的——上线即信誉事故。
2. Registry 无公网实例 + 无 HTTPS：签名体系在明文下无意义。
3. JSON 文件存储：进程崩溃可能损坏（全量重写无原子性）、无迁移路径。
4. 无 api_tokens：浏览器端无法安全调用写 API（publish/rate）。
5. 前端直接 fetch 会遭遇 CORS；当前无代理/无头。
6. 版本模型无法表达 SemVer 排序/多版本元数据（当前按对象键字符串）。
